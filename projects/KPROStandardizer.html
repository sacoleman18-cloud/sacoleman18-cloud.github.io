Kaleidoscope Pro Standardizer

A utility I built to clean and harmonize messy Kaleidoscope Pro detector outputs so teams can run analyses on one standardized structure instead of manually repairing each dataset.

At A Glance

30 Generated plots

Overview

This project solves one recurring bottleneck: Kaleidoscope Pro id.csv files from different versions do not arrive in a consistent format. The tool standardizes those files, creates a clean calls-per-night.csv for nightly analysis, and compiles a Quarto report plus release bundle that preserves every processing decision, validation step, and downstream artifact in one reproducible workflow.

R tidyverse Quarto Git YAML SHA256 registry
Why it matters
Mixed-source acoustic projects break quickly when schemas drift. This engine enforces one canonical structure, records each processing phase to an external log, and packages a complete analysis-ready release so collaborators can audit or extend the work without reconstructing what happened.

Pipeline

01

data_ingestion.R

Loads study settings, resolves source locations, and pulls raw detector exports into one tracked intake step.

  • Stage 1: Load configuration from study_parameters.yaml.
  • Stage 2: Recursively discover and load raw id.csv files from local and external source directories.
02

data_standardization.R

Normalizes version drift into a canonical master table and records exactly what was changed during cleanup.

  • Stage 3: Transform v1, v2, and v3 schemas into one unified master layout.
  • Stage 4: Map raw detector serial numbers to friendly study labels.
  • Stage 5: Convert UTC timestamps into the configured local timezone.
  • Stage 6: Finalize schema and optionally remove duplicate records.
  • Stage 7: Apply configured data filters such as NoID and zero-pulse removal.
  • Stage 8: Save checkpoints, register artifacts, and render validation output.
03

cpn_template.R

Builds the editable detector-by-night template that users can review before final nightly metrics are locked in.

  • Stage 1: Load study configuration from YAML.
  • Stage 2: Load or import standardized kpro_master data.
  • Stage 3: Optionally integrate manual IDs and create species columns.
  • Stage 4: Calculate study nights with timezone-aware aggregation.
  • Stage 5: Generate the detector by night template grid with schedule support.
  • Stage 6: Verify recording schedule settings against the intended study window.
  • Stage 7: Format the template for Excel editing, sorting, datetimes, and formulas.
  • Stage 8: Save the editable template and register the output artifact.
  • Stage 9: Render validation HTML for the template stage.
04

finalize_cpn.R

Turns the edited template into the final calls-per-night product while preserving manual changes and effort status classifications.

  • Stage 1: Reload processing configuration.
  • Stage 2: Load standardized data and editable templates.
  • Stage 3: Track manual edits applied by the user.
  • Stage 4: Calculate nightly recording hours.
  • Stage 5: Classify nights as full, partial, or no-recording and compute effort-aware metrics.
  • Stage 6: Save the final calls-per-night output.
05

summary_stats.R

Computes the summary layer used by tables, workbook exports, and downstream study-wide interpretation.

  • Stage 7: Build detector activity summaries.
  • Stage 8: Build study-wide summaries.
  • Stage 9: Estimate variance components.
  • Stage 10: Compute species composition summaries.
  • Stage 11: Compute species accumulation summaries.
  • Stage 12: Compute hourly activity summaries.
  • Stage 13: Export individual summary CSV files.
  • Stage 14: Build the Excel workbook from summary tibbles.
  • Stage 15: Export summary tables to PNG and HTML.
  • Stage 16: Save the summary RDS archive.
06

plotting.R

Generates the full report figure suite with section-aware controls and isolated failure handling for each plot.

  • Stage 17: Apply plot configuration settings.
  • Stage 18: Generate seven data-quality plots with per-plot error isolation.
  • Stage 19: Generate six detector activity plots with per-plot error isolation.
  • Stage 20: Generate eleven species composition plots with per-plot error isolation.
  • Stage 21: Generate six temporal plots with per-plot error isolation.
  • Stage 22: Export plots as PNG artifacts.
  • Stage 23: Save plot objects to RDS for reuse in other R workflows.
07

report_release.R

Assembles the final report package and makes the results portable, auditable, and easy to share.

  • Stage 24: Verify required RDS artifacts before release.
  • Stage 25: Render the final Quarto report.
  • Stage 26: Create the zipped release bundle.
  • Stage 27: Finalize validation and delivery metadata.

What The Pipeline Shows About My Work

Configurable By Design

The pipeline is driven by study_parameters.yaml, so a user can define study dates, detector mappings, time zone, filters, external data sources, and output preferences without modifying R code.

Recursive Intake For Real Projects

Instead of expecting one clean export, the intake stage can recursively discover multiple id.csv files from a configured directory, which is useful when an entire field season is organized across subfolders.

Audit Trail At Every Phase

Each stage writes to an external log.txt and updates a validation context with counts for processed rows, removed rows, duplicates, mapped detectors, time conversions, schema distribution, warnings, and errors.

Artifact Provenance And Release Packaging

Plots, tables, CSVs, RDS outputs, manifests, and report files are registered into a registry with SHA256 hashes, then bundled with the Quarto output into a portable release archive for collaborators.

Configuration And Validation Layer

study_parameters.yaml

The study file exposes the project knobs a collaborator actually needs to change between deployments.

  • Study name, study start and end dates, and local timezone.
  • Detector serial to friendly-name mapping for cleaner downstream reporting.
  • External source directory paths for importing bat detector exports.
  • Data filters such as NoID removal, zero-pulse removal, and duplicate handling.
  • Processing options including schedule handling, editable template generation, and recording windows.
  • Plot behavior controls such as NoID handling, low-night highlighting, and outlier percentile thresholds.
  • Artifact toggles that turn specific CSV, PNG, HTML, Excel, and RDS outputs on or off.

Implementation Snapshot

The implementation is built around configuration-first execution, artifact tracking, and outputs that can be reused directly in later R analyses: 

config <- load_study_config("study_parameters.yaml")
sources <- discover_id_csv_files(config$study_parameters$external_data_sources)
master <- standardize_kpro_exports(sources, config)
validation <- start_validation_context(phase_id = "data_standardization")

master <- track_schema_changes(master, validation)
cpn <- build_calls_per_night(master, config, validation)
registry <- register_artifacts_with_hashes(outputs = list(master, cpn), validation = validation)

render_quarto_report(config, registry)
build_release_bundle(config, registry, manifest = "study_manifest.yaml")
